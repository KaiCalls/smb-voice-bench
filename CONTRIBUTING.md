# Contributing

Use Python 3.10+ and the hash-locked isolated environment in the README. For archive development, install `python -m pip install --require-hashes -r requirements-dev.lock`; this additionally locks the build frontend, backend and Python 3.10 TOML reader. Run `python -m build --no-isolation`, then `python tools/check_public.py --dist dist`. The scanner verifies exact archive source bytes and the unchanged historical fixture pack. Run one bounded process with `python -m unittest discover -s tests -v`. Keep provider code, recordings, customer data, runtime prompts, account configuration and credentials outside this package.

A useful contribution reproduces a business failure with synthetic evidence and a negative control. Required invariants include: unknown never passes; denied unauthorized or duplicate decisions fail even when no record changed; unknown writes require readback; actual IDs, latest slot and intake matter; partial confirmation remains partial; missing speech cannot clear listening/timing; unmatched cohort rows and old selected failures remain visible.

To propose a case, describe its caller-authorized outcome and supply entirely fictional JSON caller turns, explicit harness-only permissions, exact timezone/slots and typed assertions. Add a faulty control and independent state checks. v0.1 stays frozen at seven cases; adding a case or changing semantic meaning requires a versioned suite/policy and contract review. Do not silently edit fixture hashes to turn a regression green. No expressions or executable fixture logic is accepted.

Keep one active work package and one test process. Use focused SQLite, importer/evaluator, comparison and browser checks. Viewer work must retain text-plus-color status, keyboard focus, 375px/1280px layouts, direct file opening, loopback preview, no autoplay and no remote requests. Source and wheel inventories must match the public allowlist. Release and outreach are separate explicit actions.
